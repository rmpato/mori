I  ·  The idea

Type mori, and today's page is open.

There is no “new entry” step. Every day already exists — most of them are simply empty — so opening mori puts a cursor on today and gets out of the way. Write a line, or a page, or nothing at all.

What you write is saved when you pause, when you stop, and when you leave. It lands in a plain Markdown file you could have written in any editor: one per day, in a folder you own. If mori disappeared tomorrow, your journal would still be there, still readable, still yours.

Horizontal moves through time, vertical moves through the page. In a one-column reading app, left and right have nothing else to mean.

II  ·  The file is the truth

A page is just Markdown.

No database. No index. No single file that can take the whole journal down with it. One small Markdown file per day, in year and month folders, written atomically and readable by anything.

~/.local/share/mori/journal/2026/08/2026-08-17.md

Today was actually pretty good.

I finally started that little Go project. #go

## 23:04

Went back to it after dinner.

The date is the filename, not a field inside it — duplicating it would only create something to disagree with. Tags are the hashtags in your prose, parsed on the way out, so tagging a day is just writing the way you already write. And a day you emptied is a day whose file is gone, because that's what you meant.

Ten years of daily writing is about three and a half thousand files and a few megabytes. Search reads all of it in the time it takes to lift your finger off the key.

🍂

III  ·  Looking back

The part that gets better with years.

A calendar shows the month with the days you wrote on picked out. Search runs as you type and answers newest-first, because looking back starts from where you are. Tags are a way in, not a filing system you have to maintain.

A month, read back

After a year of writing, a month should be able to tell you something about itself. So mori looking-back says what happened, in the past tense, and stops.

A month with two days in it prints two days and says nothing else about it. There is no line for “you haven't written lately”, because that line is the reason people abandon journals.

Open mori after three weeks away and it says welcome back. Once, without a number in it.

❄

IV  ·  A small ecosystem

Two tools, one habit.

mori has a sibling. tuki keeps the things you mean to do; mori keeps what happened. They share a face and a design language, and nothing else — either one works perfectly with the other uninstalled.

(o.o)

tuki

What do I need to do?
Tasks, tags, due dates. Energetic, a little mischievous, pointed forwards.

(-.-)

mori

What happened?
Days, writing, memory. Calm, patient, pointed backwards.

If you have both, mori can show you what you got done on a day while you decide what to say about it — press tab, or run mori today --from-tuki and get a page to write under:

# August 17, 2026

## Today

## Things I did

- Finish Go project
- Read GitOps chapter
- Go to the gym

## Things I didn't get to

- Edit photography photos

## Notes

And it stops there. Headings, and your own task text, and empty space.

tuki provides the facts.
mori provides the reflection.

mori will never write a sentence about your day and attribute it to you. That rule is the whole reason the two tools are separate, so it isn't a guideline — there is a test that walks the generated page line by line and fails on anything that is neither a heading nor a task you wrote yourself.

The integration is optional, appears only if tuki is installed, is silent when it isn't, and is read-only. Writing to tuki is not a setting. mori reads from tuki; mori does not control tuki.

🌱

V  ·  Install

However you'd normally reach for it.

$ curl -fsSL https://raw.githubusercontent.com/rmpato/mori/main/install.sh | sh

Installs to ~/.local/bin and adds it to your PATH if it isn't there already. The download is checked against the release's own sha256 before anything is written.

Options: --dir, --version, --no-modify-path.

$ go install github.com/rmpato/mori@latest

This lands in $(go env GOPATH)/bin — usually ~/go/bin, which isn't on your PATH by default.

$ git clone https://github.com/rmpato/mori
$ cd mori
$ make install

Go 1.26 or newer. make check runs the formatter, vet, and the tests.

Take an archive for your platform from the releases page, unpack it, and move mori somewhere on your PATH.

macOS, Linux, and Windows; amd64 and arm64.

Staying current

$ mori update

mori checks for a newer version, shows what changed, and asks before replacing anything. The binary being replaced is kept aside until the new one is safely in place. It is the only command that touches the network, and your journal is never part of it.

It behaves in a pipe

When output isn't a terminal, mori hands you the file rather than a drawing of it. Every printing command takes --plain and --json.

$ mori today | wc -w
$ mori search photography --json | jq -r '.[].date'
$ mori tags | sort -k2 -rn
$ $EDITOR "$(mori path yesterday)"

VI  ·  What mori doesn't do

Journaling, not measuring.

  • accounts or sync
  • cloud, ever
  • streaks
  • word-count goals
  • mood charts
  • notifications
  • telemetry
  • gamification

Numbers appear in mori only when they are being interesting, never when they are being a scoreboard. The mood field is one optional word that renders as a quiet dot beside the date — there is no scale, no average, no trend, and mori never says anything back about it.

Your journal is stored at 0600 in a directory only you can read, because it is a diary and the default umask isn't careful enough for one. There is nothing to log in to, nothing to be online for, and nothing sent anywhere.

This page makes no network requests either. No fonts, no analytics, no third-party anything — it seemed like the least a page about a private journal could do.

🍂

VII  ·  Built with

Small parts, chosen once.

  • Bubble Teathe interface
  • Lip Glossthe styling
  • Bubblestextarea, viewport, help
  • Fangthe command line

Written in Go, in seven small packages: the domain knows nothing but the standard library, storage knows nothing about the interface, and the terminal and the command line are two presentation layers over one journal. The design notes say why, and a local web interface is being designed to sit alongside them.
